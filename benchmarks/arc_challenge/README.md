# ARC-AGI Benchmark (`benchmarks/arc_challenge`)

Adapts tasks from the [ARC-AGI benchmark](https://arcprize.org/) ("Easy for Humans, Hard for AI") to this
project's `BenchmarkTask` structure so the multi-evaluator optimisation loop can evolve agents on abstract
grid-reasoning puzzles alongside the 7 canonical coding tasks.

## The data format

The Kaggle arc-prize datasets (and OpenEvolve's example) ship each split as **two multi-task JSON files**,
not one file per task. Test outputs are kept in a separate solutions file so the challenges file can be
published for hidden splits:

```
arc-agi_{split}_challenges.json   {"00576224": {"train": [{"input": Grid, "output": Grid}, ...],
                                                "test":  [{"input": Grid}, ...]}, ...}
arc-agi_{split}_solutions.json    {"00576224": [Grid, ...]}      # one output per test input, same order
```

`split` is `training`, `evaluation` or `test`. A grid is a rectangular list-of-lists of ints `0-9`
(0 = background), 1x1 up to 30x30. `train` holds the demonstration pairs (typically 3), `test` the held-out
input(s) (typically 1, sometimes 2). `benchmarks/arc_challenge/data/` holds a 4-task sample in exactly this
layout; `ARC_DATA_ROOT` points the loader at a full Kaggle download and `ARC_TASK_FILE` restricts it to one
split (defaults: bundled sample, every split present).

**Scoring** (per ARC Prize rules): an output is correct only if it is pixel-perfect — same shape, every cell
equal. Two attempts are allowed per test input; a task is solved if either matches (**pass@2**). Pixel
accuracy is a secondary diagnostic only, never the leaderboard metric.

## Mapping onto `BenchmarkTask`

| ARC field | `BenchmarkTask` field | Evaluator that consumes it |
| :--- | :--- | :--- |
| `train` pairs | `test_cases` — `{"args": (input,), "expected": output}` | μ₁ Functional Correctness (fit the demonstrations) |
| `test` pairs | `edge_cases` — same shape | μ₅ Edge-Case Stress (generalise to the held-out input) |
| task id `00576224` | `id="arc_00576224"`, `name="ARC 00576224: …"` | task selector / CSV `task_id` |
| — | `entry_point="solve"`, `solve(grid) -> grid` | `CodeExecutionRunner` |
| rendered grids | `description` (prompt shown to the agent) | agent LLM, μ₄ judge |

Only the demonstration pairs are used for the agent's fitness signal (μ₁); held-out pairs are scored
separately (μ₅), which mirrors the OpenEvolve split of evolving on `train` and evaluating on `test`.
`CodeExecutionRunner` normalises numpy arrays via `.tolist()` before comparing, so `solve` may return either.

## Evaluators

**Real** (`evaluators.py`) — the metrics an actual ARC submission is judged on, in the shape OpenEvolve's
evaluator reports them. Nothing here is invented.

| Evaluator | Score |
| :--- | :--- |
| `arc_runs_successfully` | 1 if the program loads, exposes `solve` / `transform_grid_attempt_1/2`, and no attempt raises (OpenEvolve `runs_successfully`) |
| `arc_pass_at_2_train` | mean pass@2 over demonstration pairs (OpenEvolve `combined_score` during evolution) |
| `arc_pass_at_2_test` | mean pass@2 over held-out pairs — the official task score |

**Partial credit** (`partial_evaluators.py`) — **AI-generated by Claude**, flagged by the 4-line header at the top
of the file (also exported as the `AI_GENERATED_HEADER` constant and `details["ai_generated"] = True` on every
result). They exist only to give the GP-weighted fitness a gradient before a candidate hits an exact match;
they are not ARC metrics and must never be reported as ARC results. Each scores the best of the (≤2) attempts
per demonstration pair, then averages over pairs.

| Evaluator | Score |
| :--- | :--- |
| `arc_pixel_accuracy` | fraction of correct cells (0 on shape mismatch) |
| `arc_shape_match` | fraction of outputs with the right `(rows, cols)` |
| `arc_color_palette` | colour-histogram intersection with the expected grid, shape-agnostic |

**No tiers, no cost.** Every ARC evaluator is registered as `core` at `$0.000`: each one just executes `solve()`
on grids, so unlike the canonical suite (where μ₄/μ₆ are LLM judges at $0.015 a call) there is nothing worth
pruning. Consequences: the selective-search strategies (`full_adaptive`, `static_cascade`) run all six
evaluators every generation, the official `arc_pass_at_2_test` is present for every candidate, and fitness
reduces to Σ wⱼμⱼ (the λ·cost term is 0). Cost-saving telemetry is therefore not meaningful on ARC; the ARC
experiment is about whether GP-weighted multi-evaluator fitness finds solving programs. Only the opt-in
`include_llm_judges=True` adds deep-tier evaluators, since those do cost a call.

Example on task `c8f0f002` (recolour 7→5) with a program that applies the rule to every row but the last:
`arc_pass_at_2_train = 0.0`, `arc_pixel_accuracy = 0.84`, `arc_shape_match = 1.0`, `arc_color_palette = 0.84`.

## Running ARC as one benchmark

ARC is selected as a single benchmark (`arc_benchmark` / "ARC-AGI Benchmark (all loaded tasks)"), never as
individual puzzles. Each generation the candidate agent is run on **every loaded task** (one LLM call per task),
each task is scored by the active evaluator subset, and then:

- **scores are averaged across tasks** — so `arc_pass_at_2_test` is the fraction of the benchmark solved, i.e.
  the official ARC score (for tasks with two held-out inputs, both must match to count as 1.0);
- **evaluator costs are summed across tasks** — naive cost is `pool cost × n_tasks`, so the cost-penalty and
  pruning telemetry stay honest;
- per-task programs and scores are kept on the agent (`task_solutions`, `task_metrics`) and in the generation
  record (`task_metrics`) behind the averaged `metrics`.

The bundled sample is 4 tasks. With a full Kaggle download (`ARC_DATA_ROOT`) that is 120–1000 LLM calls per
generation; use `ARC_TASK_FILE=evaluation` and `ARC_TASK_LIMIT=N` to cap it.

## Visualisation (Streamlit)

`uv run streamlit run app.py` → sidebar **Evaluator Suite → ARC-AGI (3 real + 3 partial)**, pick
**ARC-AGI Benchmark (all loaded tasks)**, run generations, open the **ARC BENCHMARK: Grid Results** tab:

- **Benchmark KPIs** — averaged pass@2 (demonstrations / held-out with "k / n tasks solved"), pixel accuracy,
  fitness. (A metric the selective search pruned for a candidate would show `— (pruned)`; with the flat ARC
  pool this only happens when LLM judges are opted in.)
- **Per-task table** — every task's scores for the selected candidate with a `Solved` flag.
- **Grid gallery** — pick a task of the run; one row per demonstration / held-out pair: Input | Expected |
  Predicted, drawn in the official ARC colour palette. Titles show `✓ exact` or `✗ NN% px`; if only
  `transform_grid_attempt_2` is correct, that attempt is shown so the pass@2 credit is visible.
- **ARC scores over generations** — real metrics as solid lines, AI-generated partial-credit ones dashed.
- **Best-so-far per ARC task** — across all candidates, with an official `Solved` flag.

The rest of the dashboard follows the active suite: tier captions, active-evaluator counts, GP target metric,
activation heatmap and the Pareto scatter (axes become pass@2-train × pixel-accuracy). Switching suites rebuilds
the controller, since the GP and archive are keyed on the metric set. The functions in `viz.py` are plain plotly
(`task_gallery_figure`, `pass_at_2_trajectory_figure`, `benchmark_summary_frame`) and work outside Streamlit.

## Usage

```python
from benchmarks.arc_challenge import (
    ARC_BENCHMARK_ID, ARC_TASKS, build_arc_evaluator_pool, get_arc_task, load_arc_tasks, load_kaggle_split,
    score_arc_program,
)
from controller import EvolutionController

# Whole ARC benchmark per generation with the ARC evaluator suite (3 real + 3 partial)
ctrl = EvolutionController(selected_task_id=ARC_BENCHMARK_ID, evaluator_pool_factory=build_arc_evaluator_pool)
rec = ctrl.run_generation()
# rec["metrics"]["arc_pass_at_2_test"]  -> fraction of tasks solved (official score)
# rec["task_metrics"]["arc_00576224"]   -> that task's scores
# ctrl.metric_names == ['arc_runs_successfully', 'arc_pass_at_2_train', 'arc_pass_at_2_test',
#                       'arc_pixel_accuracy', 'arc_shape_match', 'arc_color_palette']

# Full Kaggle dataset (https://www.kaggle.com/competitions/arc-prize-2025/data), same layout OpenEvolve uses.
# Either set ARC_DATA_ROOT=/path/arc-prize-2025 (and optionally ARC_TASK_FILE=evaluation) before import, or:
tasks = load_kaggle_split("data/arc-prize-2025", split="evaluation", limit=10)   # order == arcprize.org/tasks
tasks = load_arc_tasks("data/arc-prize-2025")                                    # every split present

# Optional pass@2 scoring for programs exposing transform_grid_attempt_1/2 (or a lone solve)
metrics = score_arc_program(get_arc_task("00576224"), program_text, use_held_out=True)
# -> {"runs_successfully": 1.0, "combined_score": 1.0, "test_example_0_pass_at_2": 1,
#     "test_example_0_attempt_0": True, "test_example_0_attempt_1": True, ...}
```

To add tasks to the bundled sample, append entries to the matching `data/arc-agi_{split}_challenges.json`
(train pairs + test inputs) and `_solutions.json` (test outputs) and optionally a label in
`loader.ARC_TASK_LABELS`. Per-task files from `fchollet/ARC-AGI` can still be loaded one-off with
`load_arc_task_file(path)`.

## Offline / mock mode

`GroqLLMClient` in mock mode recognises the `ARC-AGI task <id>` prompt header and returns hand-written
solutions for the four bundled tasks (identity transform for any other id), consistent with how it mocks
the seven coding tasks. Real evaluation of unseen ARC tasks requires a live `GROQ_API_KEY`.

## Design notes / differences from OpenEvolve's example

- OpenEvolve evolves a program with **two** functions (`transform_grid_attempt_1/2`) and its evaluator computes
  pass@2 over them. The ARC evaluators here accept either those two functions or a lone `solve` (pass@1 then).
  The canonical μ₁/μ₅ path is single-entry-point `solve` only.
- OpenEvolve reads the Kaggle split files via `DATA_ROOT` / `TASK_FILE` / `TASK_NUM`; here that is
  `ARC_DATA_ROOT` / `ARC_TASK_FILE`, and `load_kaggle_split(..., limit=N)` keeps the challenges-file order so
  index `N` matches "Task N" on arcprize.org.
- Fitness = Σ wⱼμⱼ (all cⱼ = 0) mixes real and partial evaluators. Only `arc_pass_at_2_test` is comparable to a
  published ARC score.
- Prompt wording avoids `target`, `differ`, `stock`, `fib`, `bracket`, `parenthes`: the mock client keyword-matches
  on those to pick canonical-task solutions (see `tests/test_arc_challenge.py`).
